Server owner guide

Terrascape Quick Start

Install the server mod, check your map, and configure player access.

Start setup Using the map

Defaults: local access only · web port 5960 · no map token required

Before you configure

Install and check the local map

  1. Download the latest jar from CurseForge.
  2. Stop your Hytale dedicated server. Place Terrascape-<version>.jar in <save>/mods/.
  3. Start the server and check the log for Terrascape started.
  4. On the server computer, open http://127.0.0.1:5960. Your map should load.

For a map used only on that computer, the defaults are enough. To share it, work through the four settings below.

One configuration file

<save>/mods/com.codelabchaos_Terrascape/terrascape.properties

Terrascape creates this file on first start. Stop the server before editing and restart afterward.

Find the active path with /terrascape status or the startup log entry Terrascape config loaded from.

1

Choose who can view the map

Decide who can view the map once they can reach it.

ModeWho can viewUse when
public defaultAnyone who can reach the web portLocal or LAN only, or you want an open map
restrictedOnly visitors with a valid generated linkYou want to require a personal link, including for a private internet-facing map
 
access.mode=restricted

With restricted, grant permission to a group or an individual player using one of these commands. Players then run /terrascape maplink in-game:

/perm group <group> add terrascape.map.use
/perm user <player> add terrascape.map.use

Network reachability and access mode are separate choices. A firewall controls who can connect; access.mode controls whether those visitors need a link.

2

Connect your network

By default the map only listens on the server machine at http://127.0.0.1:5960. To open it to other computers:

http.host=0.0.0.0
http.port=5960
KeyDefaultWhat it does
http.host127.0.0.1Address the map listens on. 0.0.0.0 means every network interface (it is not an address visitors type).
http.port5960TCP port for the web map. Change it to whatever your host assigns.

Then open the port

  • Allow the TCP port through the server firewall and any hosting control panel.
  • Behind a home router, forward that TCP port to the server machine.
  • On a hosted server, ask the provider for an extra TCP port. The Hytale game port does not carry web-map traffic.

Visitors then open http://<server-address>:5960.

Behind a reverse proxy on the same machine? Leave http.host=127.0.0.1 and let the proxy forward to it. Remote command service (RCON, port 25578) is off by default and not needed for the map; never expose it publicly.

3

Set the address players will use

Without this, /terrascape maplink builds links from the listening address, which can come out as 0.0.0.0, localhost, or a raw IP. Set the address visitors should actually use:

access.publicBaseUrl=https://map.example.com

Include the port if visitors have to type it:

access.publicBaseUrl=http://map.example.com:5960

This only changes the generated links. It doesn't set up DNS, TLS, the listening address, or the firewall. For HTTPS, point your domain at the server and put a reverse proxy (or your host's HTTPS feature) in front of Terrascape.

4

Choose how long links last

Generated personal links expire after a set number of hours. In restricted mode, opening a link creates a browser session valid until that expiry. When the viewer shows map access expired, the player needs a fresh link. Personal console access also expires on public maps.

access.mapTokenTtlHours=24
access.adminMapTokenTtlHours=4
KeyDefaultApplies to
access.mapTokenTtlHours24Ordinary player links
access.adminMapTokenTtlHours4Links made by admins (they carry admin web capabilities, so keep them short)

Both accept whole hours from 1 to 8760 (one year). Treat links like passwords while they are valid.

Finish setup

Restart, then test as a player

This example uses a restricted map and an HTTPS reverse proxy on the server computer. Configure your domain and proxy before sharing the link.

access.mode=restricted
http.host=127.0.0.1
http.port=5960
access.publicBaseUrl=https://map.example.com
access.mapTokenTtlHours=24
access.adminMapTokenTtlHours=4

If visitors connect directly to the web port instead, use http.host=0.0.0.0, allow the assigned TCP port, and set access.publicBaseUrl to the reachable address, including its port.

  1. Restart the server to apply your changes.
  2. Grant terrascape.map.use to the player or group that needs access.
  3. Run /terrascape maplink in-game and open the generated link from a player's computer.
  4. Check that the map loads and the link uses the public address you configured.

A working map from a player's computer confirms the access and network setup. If it fails, use the troubleshooting checks below.

NodeGrants

terrascape.adminAdmin subcommands and admin-scoped links. Trusted staff only. A custom admin group needs both nodes.

Removing a permission doesn't kill links already made. Find the player's Link ID with /terrascape tokens and revoke it. To invalidate every link, stop the server, delete access-tokens.json, and start it again.

Limit visible worlds 
worlds.allowlist=world1,world2

Blank (the default) shows every loaded world.

Web chat console

Personal links can open a chat and command panel with T. Commands run with the linked player's own Hytale permissions; anonymous visitors never get it. Turn it off with features.webConsole=false.

Server load

server-config.json (same folder) caps what the browser viewer may request: stream radius, map-tile radius, load concurrency, mob and player update rates. Lower these first if the server is working too hard.

Remote or headless server auth

Use /auth login device and complete the URL and code printed in the console. Check with /auth status. This is Hytale's auth and is separate from map links.
